# dsh-testmng

DeepSeek Harness（DSH）测试管理平台插件，用于统一管理测试管理平台的核心内容：**项目、需求、用例、执行、报告**。

## 项目定位

本插件是 DSH 生态中的一个功能插件，为测试管理平台提供一套可编程、可自动化、可被 AI Agent 调用的领域能力。以插件形式发布，业务方可通过「配置加载 + 能力注册」的方式接入自己的测试管理平台，实现测试资产的结构化管理与智能调度。

## 能力范围

| 模块 | 说明 |
| ---- | ---- |
| 项目 Project | 测试项目的创建、维护、归档、成员与权限管理 |
| 需求 Requirement | 测试需求的录入、版本、状态流转、与用例的关联 |
| 用例 Case | 用例的增删改查、目录组织、步骤设计、批量导入导出 |
| 执行 Execution | 测试计划、执行批次、执行结果记录、缺陷关联 |
| 报告 Report | 执行统计、覆盖率、趋势分析、报告生成与导出 |

## 整体架构

```
dsh-testmng
├── core/                  # 领域核心：实体、仓库接口、领域服务
│   ├── models/            # 数据模型（项目 / 需求 / 用例 / 执行 / 报告）
│   ├── repositories/      # 存储抽象接口（支持多后端实现）
│   └── services/          # 领域服务（业务规则与编排）
├── api/                   # DSH 插件对外能力接口（tools / MCP / HTTP）
│   ├── tools/             # 面向 AI Agent 的工具定义
│   └── routers/           # 面向外部系统/前端的 HTTP 路由
├── adapters/              # 适配层：接入不同测试管理平台的实现
├── storage/               # 存储实现（文件 / 数据库，可插拔）
├── schemas/               # 输入输出校验 Schema
├── tests/                 # 单元与集成测试
└── claudedocs/            # 设计文档与说明
```

## 数据模型

### 项目 Project
- 项目名称、编码、描述、状态（草稿 / 进行中 / 已归档）
- 成员与角色（管理员 / 测试人员 / 开发 / 观察员）
- 起止时间、所属组织

### 需求 Requirement
- 需求标题、描述、优先级、版本
- 状态流转：新建 → 评审 → 已确认 → 开发中 → 已上线 → 已关闭
- 与用例的一对多关联

### 用例 Case
- 标题、前置条件、步骤（步骤 / 预期结果）、优先级、类型
- 目录树组织、标签、关联需求
- 状态：草稿 / 已评审 / 已执行 / 已归档

### 执行 Execution
- 执行计划：时间窗口、执行人、关联用例集
- 执行记录：单条用例执行结果（通过 / 失败 / 阻塞 / 跳过）、实际结果、耗时
- 缺陷关联：失败用例可关联 BUG 记录

### 报告 Report
- 汇总统计：总数 / 通过率 / 失败率 / 阻塞率
- 覆盖率：按需求、按模块的用例覆盖情况
- 趋势分析：多批次执行结果对比
- 输出格式：Markdown / HTML / Excel

## 插件接入方式

1. **加载**：将插件目录加入 DSH 配置或通过插件注册入口加载。
2. **配置**：指定存储后端、平台适配器、权限策略。
3. **注册**：插件启动时向 DSH 注册领域服务与工具能力，供 Agent 调用。
4. **调用**：通过统一接口完成对测试管理平台内容的读写与自动化。

## 典型场景

- **智能用例生成**：根据需求描述自动生成用例草稿，人工评审后入库。
- **批量回归执行**：按需求/版本筛选用例，自动编排执行计划并汇总结果。
- **自动报告输出**：执行完成后自动生成报告，推送至团队。
- **需求覆盖率检查**：实时统计需求关联用例情况，标记未覆盖需求。
