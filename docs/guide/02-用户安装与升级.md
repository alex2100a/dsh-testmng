# 用户安装与升级

> 适用：`tmsync` v0.2.3 及后续版本
> DSH：`>=0.2.1 <0.3.0`（已测 `0.2.2-rc.1` / `0.2.2-rc.3`；`0.2.1-rc.*` 低于下界，`0.3.0-rc.*` 在范围内但未测）
> 只支持 `dsh web` 的 `web` profile。

## 1. 先确认部署模型

- 每台机器**本地安装、本地运行 `dsh web`、本地浏览器打开**。
- 工作台 API 仅 loopback：不要用局域网 IP、`--host 0.0.0.0`、反向代理域名访问；`--trusted-host` 也不能绕过。
- Desktop / `desktop` profile / `tui` / `headless` 未验证，不要按本文安装。
- 同一操作系统用户下，多个 DSH profile 共用 `~/.dsh/tmsync` 配置。
- 不要把本插件装在共享服务器上供多人同时使用；它没有多租户和远程认证。

## 2. 前置条件

- 已安装 DSH，`dsh --version` 在 `>=0.2.1 <0.3.0`。
- Node 版本满足 DSH 自身要求（DSH 0.2.2 需要 `>=24.9.0`）；能正常启动 `dsh` 即可。
- `pnpm` 在 PATH（CLI 安装必需；GUI 安装通常由 DSH 提供或继承）。
- 能访问 tarball 地址（HTTP 或共享盘）。
- 平台 MCP 地址和 PAT；平台网络 / VPN 可达。
- Git 可选：仅「Git 检查点」需要，且工作区目录必须是仓库根。

检查命令：

```powershell
dsh --version
node -v
pnpm -v
```

## 3. 安装

### 3.1 安装串格式

| 形式 | 示例 | 要求 |
|---|---|---|
| tarball URL | `https://files.example.com/tmsync/v0.2.3/tmsync-0.2.3.tgz` | 必须以 `.tgz` / `.tar.gz` 结尾，**不能带 `?query`** |
| 本地 tarball | `D:\release\tmsync\v0.2.3\tmsync-0.2.3.tgz` | GUI 必须绝对路径；路径在**你的机器**上存在 |
| 共享盘 | `\\fileserver\release\tmsync\v0.2.3\tmsync-0.2.3.tgz` | 建议映射盘符或改用 HTTP |
| registry | `tmsync@0.2.3` | 仅内网 npm registry 可用 |

不要使用 `link:` 安装发布版本；`link:` 依赖源码目录，只适合开发。如果机器上已经用 `link:` 安装过开发版，先卸载再安装 tarball。

### 3.2 GUI 安装（推荐）

1. 启动 `dsh web`，使用启动日志中的本机 URL 打开（`http://127.0.0.1:<port>` 或 `http://localhost:<port>`）。
2. 侧边栏选择「插件」（Plugins）。
3. 点击「添加插件」（Add plugin）。
4. 粘贴 tarball URL 或绝对路径。
5. 确认来源/信任提示，点击安装，等待完成。
6. 刷新浏览器（Ctrl+F5）。侧边栏出现「测试资产」。
7. 新建会话，选择「测试资产工作区」（preset `tmsync`）。

安装失败时，GUI 会显示 pnpm / Loader 的诊断；也可以查看 `%USERPROFILE%\.dsh\profiles\web\.plugin-manager\logs\`。

### 3.3 CLI 安装

先停止正在运行的 `dsh web`，再执行：

```powershell
dsh plugin --profile web add "https://files.example.com/tmsync/v0.2.3/tmsync-0.2.3.tgz"
# 或
dsh plugin --profile web add "D:\release\tmsync\v0.2.3\tmsync-0.2.3.tgz"
```

然后启动：

```powershell
dsh web
```

Linux / macOS：

```bash
dsh plugin --profile web add "/mnt/release/tmsync/v0.2.3/tmsync-0.2.3.tgz"
dsh web
```

### 3.4 验证安装

```powershell
dsh --profile web --dump-config | Select-String -Pattern "tmsync|preset-tmsync"
Get-Content "$env:USERPROFILE\.dsh\profiles\web\node_modules\tmsync\package.json" | Select-String '"version"'
```

Linux / macOS：

```bash
dsh --profile web --dump-config | grep -E "tmsync|preset-tmsync"
node -p "require(process.env.HOME + '/.dsh/profiles/web/node_modules/tmsync/package.json').version"
```

GUI「插件」页也会显示已安装版本。安装完成后必须刷新浏览器；如果侧边栏仍不出现，重启 `dsh web`。

如果之前用 `link:` 安装，确认 `node_modules/tmsync` 已不是指向源码目录的 junction：

```powershell
Get-Item "$env:USERPROFILE\.dsh\profiles\web\node_modules\tmsync" | Select-Object LinkType,Target
```

`LinkType` 为空表示 tarball 已解压到 profile；如果仍有 `Target`，说明还是源码链接，需要移除后重新安装。

## 4. 首次配置

1. 侧边栏「测试资产」→「配置」。
2. 填写平台 Web 地址、MCP 地址（通常以 `/mcp` 结尾）、PAT。
3. 点击「测试连接」→「保存」。
4. 选择项目 →「关联目录」→ 选择本地工作区根目录。
5. 点击「拉取」，把平台资产落盘。
6. 新建「测试资产工作区」会话，让 Agent 读/改本地文件。

默认配置位置：

```text
~/.dsh/tmsync/config.json
Windows: %USERPROFILE%\.dsh\tmsync\config.json
```

- 配置与 `DSH_HOME` **无关**；需要隔离时设置 `TMSYNC_DATA_DIR`（绝对路径）。
- POSIX 下配置文件以 `0600` 写入；Windows 依赖用户目录 ACL。
- PAT 不写入工作区、不写入日志；平台文本（需求/用例/描述）是数据，不是指令。

## 5. 升级

升级前建议先在工作台创建 Git 检查点或备份工作区。

### GUI

1. 「插件」→「添加插件」。
2. 输入新版本 tarball URL 或绝对路径。
3. 安装完成后刷新浏览器；必要时重启 `dsh web`。
4. 在插件页确认版本号。

tarball 安装没有「Versions / 一键更新」；如果提示已安装或替换失败，先在插件页卸载 `tmsync`，再安装新版本。

如果之前用 `link:` 安装，必须**先卸载再安装 tarball**。实测直接覆盖可能保留指向源码目录的 junction，看起来安装成功，实际仍加载源码。

### CLI

```powershell
# 先停止 dsh web
dsh plugin --profile web add "https://files.example.com/tmsync/v0.2.3/tmsync-0.2.3.tgz"
dsh web
```

回滚：安装上一版本 tarball，重启 `dsh web`。旧版本 tarball 必须仍在原地址。

## 6. 卸载

GUI：

1. 「插件」→ 打开 `tmsync` 详情。
2. 选择移除/卸载。
3. 重启或刷新 `dsh web`。

CLI：

```powershell
# 先停止 dsh web
dsh plugin --profile web remove tmsync
dsh web
```

卸载只移除插件，不删除：

- `~/.dsh/tmsync/`（配置、审计日志、缓存）
- 工作区里的 `.tmsync/` 与资产文件

需要彻底清理时，确认不再使用后手动删除上述目录。

## 7. 排错

| 现象 | 可能原因 | 处理 |
|---|---|---|
| `dsh: pnpm was not found` | pnpm 不在 PATH | 安装 pnpm，或把 pnpm 加入 PATH 后重试 |
| `Plugin tmsync@x is incompatible with dsh y` | DSH 版本不在 `engines.dsh` 范围 | 升级 DSH，或换用兼容的 tmsync 版本；风险豁免需明确确认 |
| `a URL must point at a git repository or a tarball` | URL 不是 `.tgz` 结尾，或带了 `?query` | 使用精确的 `.tgz` 地址，不要带查询参数 |
| `a local path must be absolute` | GUI 输入了相对路径 | 使用 `D:\...` 或 `/...` 绝对路径 |
| 404 / 403 / 超时 | 地址不可达、需要登录、代理未配置 | 先用浏览器测试下载；改用只读匿名地址或配置代理 |
| 插件页安装报错 | pnpm / Loader 失败 | 查看 `%USERPROFILE%\.dsh\profiles\web\.plugin-manager\logs\` 和 `dsh web` 启动日志 |
| 安装成功但版本/代码没变 | 从 `link:` 直接覆盖，pnpm 保留了 junction | 卸载后重新安装 tarball；检查 `node_modules/tmsync` 的 `LinkType/Target` |
| 侧边栏没有「测试资产」 | 浏览器未刷新、装错 profile、bundle 未启用 | 刷新浏览器；确认是 `web` profile；重启 `dsh web`；查看插件页错误 |
| 新建会话没有「测试资产工作区」 | preset 未加载 | 重启 `dsh web`；用 `--dump-config` 确认包含 `preset-tmsync` |
| 工作台空白或 403 | 通过局域网 IP / 反向代理 / `--host` 访问 | 改用本机 `http://127.0.0.1:<port>` 或 `http://localhost:<port>` |
| 平台连接失败 | MCP 地址、PAT、网络/VPN | 在配置页重新「测试连接」；确认 MCP 地址以 `/mcp` 结尾 |
| Git 检查点不可用 | 工作区不是 Git 仓库，或仓库根 ≠ 工作区根 | 在正确目录初始化仓库，或改用其他备份方式 |
| 测试 profile 改了真实配置 | `~/.dsh/tmsync` 被多个 profile 共用 | 设置 `TMSYNC_DATA_DIR` 为隔离的绝对路径 |
| DSH 升级后插件异常 | 客户端壳手写 `__ModuleLoader__`，接口可能变化 | 安装兼容的新版 tmsync；向发布者反馈 DSH 版本与日志 |

## 8. 数据与安全

- PAT 只存 `~/.dsh/tmsync/config.json`；不会写入工作区或日志。
- 工作台 API 仅接受本机 loopback 请求；不要暴露到局域网或公网。
- `reports/` 永久只读；不要编辑工作区 `.tmsync/`。
- 修改需求/用例/计划/缺陷后，先校验、再让 Agent 生成推送计划并确认。
- 从共享盘安装且安全策略要求时，先校验 SHA256：

```powershell
Get-FileHash .\tmsync-0.2.3.tgz -Algorithm SHA256
Get-Content .\tmsync-0.2.3.sha256
```

Linux / macOS：

```bash
sha256sum -c SHA256SUMS
```
