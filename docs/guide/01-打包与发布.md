# 打包与发布（发布者）

> 适用：`tmsync` v0.2.3 及后续版本
> 分发方式：HTTP / 共享盘 tarball（不发布到公网 npm）
> 相关：[用户安装与升级](02-用户安装与升级.md)｜[指南索引](README.md)

## 1. 发布模型

- 发布物是 `npm pack` 生成的 `tmsync-<version>.tgz`。
- 同一版本只发布一次，产物不覆盖；升级用新版本号。
- 用户通过 GUI「插件」页或 `dsh plugin --profile web add` 安装。
- `package.json` 保留 `"private": true`，防止误执行 `npm publish`。
- 本插件只适用于 `web` profile；工作台 API 仅 loopback，**不是多人共享服务**。

## 2. 发布前检查

### 2.1 版本单一来源

| 位置 | 内容 |
|---|---|
| `server/version.js` | `VERSION = '0.2.3'`（唯一来源） |
| `package.json` | `"version": "0.2.3"` |
| `server/mcp.js` | `CLIENT_INFO = { name: 'tmsync', version: VERSION }` |
| `server/service.js` | `info().version = VERSION` |
| `README.md` | `> 当前为 **v0.2.3**：...` |
| `CHANGELOG.md` | `## v0.2.3 — ...` |

`npm run release:check` 会校验 `server/version.js` 与 package/README/CHANGELOG/guide 一致；mcp/service 必须引用 `VERSION`，不得再写死。

### 2.2 包名与引用

包名必须保持 `tmsync`。以下 3 处引用任何一处改了都会导致 preset 加载失败：

- `cordis.patch.yml`：`name: 'tmsync'`
- `preset/tmsync/preset.patch.yml`：`name: 'tmsync/tools'`
- 同文件：`resolve('tmsync/package.json')`

`release:check` 会校验。若将来改用 scope 名，必须同时修改这三处，并在干净 profile 里复跑 host smoke。

### 2.3 打包边界

发布包只包含运行所需文件：

```text
lib/           宿主半 + 客户端半 + Agent 工具
server/        工作台 API、同步、平台适配
public/        工作台静态资源（HTML/CSS/JS）
preset/        tmsync preset 与 skills
cordis.patch.yml
README.md
CHANGELOG.md
docs/guide/    发布与安装指南
```

不包含 `scripts/`、`test/`、`docs/design/`、`node_modules/`、`.tmsync/`、`data/`。

### 2.4 测试

```powershell
npm run test:unit
npm run check:links
```

`npm run release:check` 会串联执行，并额外做版本、包名引用与打包白名单校验。

## 3. 打包

先提交代码（`release:pack` 默认要求工作树干净）：

```powershell
git add -A
git commit -m "release: v0.2.3"
git tag v0.2.3
npm run release:pack
```

产物：

```text
dist/
  tmsync-0.2.3.tgz
  tmsync-0.2.3.sha256
  SHA256SUMS
  INSTALL.md
  CHANGELOG.md
  guide/
```

校验：

```powershell
Get-FileHash dist\tmsync-0.2.3.tgz -Algorithm SHA256
Get-Content dist\tmsync-0.2.3.sha256
```

Linux / macOS：

```bash
sha256sum dist/tmsync-0.2.3.tgz
cd dist && sha256sum -c SHA256SUMS
```

本地试打包（不发布）可跳过干净树校验：

```powershell
node scripts/release-pack.js --allow-dirty
```

同版本产物已存在时脚本会拒绝覆盖；请先提升版本号。

## 3.1 CI 自动发布（v0.2.3+）

仓库提供两条 GitHub Actions：

- `.github/workflows/pr-checks.yml`：PR/手动触发；Ubuntu + Windows、Node 22.19/24；跑 `test:unit`、`check:links`；Linux 额外跑 `check-release` 并产出 `dist/` artifact。
- `.github/workflows/release.yml`：推送 `v*` tag 触发；校验 tag == `package.json.version`；跑 `release:check`、`release-pack`，创建 GitHub Release，附 tgz、`.sha256`、`SHA256SUMS`、`INSTALL.md`、`CHANGELOG.md`。

操作：

```powershell
git tag v0.2.3
git push origin v0.2.3
```

> 当前仓库没有配置 GitHub remote，因此 P4/P5 只能做本地 workflow 静态检查 + 脚本门禁；证据中必须标注“workflow 未实跑”，不得声称 CI 已通过。配置 remote 后按上面的 tag 流程实跑。

## 4. 上传共享盘 / HTTP

推荐布局（版本目录不可变）：

```text
\\fileserver\release\tmsync\
  v0.2.3\
    tmsync-0.2.3.tgz
    tmsync-0.2.3.sha256
    SHA256SUMS
    INSTALL.md
    CHANGELOG.md
    guide\
  v0.2.3\
    ...
  latest.txt          # 可选：只写当前版本号，例如 0.2.3
```

PowerShell 上传示例：

```powershell
$target = "\\fileserver\release\tmsync\v0.2.3"
New-Item -ItemType Directory -Force $target | Out-Null
Copy-Item dist\* $target -Recurse -Force
```

HTTP 发布示例：

```text
https://files.example.com/tmsync/v0.2.3/tmsync-0.2.3.tgz
```

上传后用浏览器或 `Invoke-WebRequest` 验证能直接下载到 tarball，而不是登录页或 HTML 错误页。

### 4.1 必须遵守的规则

- **不可变**：同一版本不覆盖；旧版本保留，供用户回滚和 `pnpm install` 重放。
- **文件名用 ASCII**：顶层发布附件用 `tmsync-0.2.3.tgz`、`INSTALL.md`、`SHA256SUMS`；避免空格、中文和特殊字符。`guide/` 内的中文文档名可保留。
- **URL 以 `.tgz` 结尾**：DSH 只接受 `.tgz` / `.tar.gz` 结尾的 tarball URL，且**不接受 query string**；预签名 URL（`?token=...`）不可用。
- **用户可达**：发布机的本地路径对同事无意义；共享盘路径必须是用户能访问的 UNC 或映射盘，优先 HTTP 直链。
- **只读权限**：用户只需读取；不要给写权限。
- **长期保留**：profile 的 `package.json` 会记录安装时的 URL/路径；删除文件会导致以后 `pnpm install` 失败。
- **UNC 路径**：Windows 共享盘建议映射盘符或改用 HTTP；安装前用普通用户账号实际访问一次。
- **不要用 `latest` URL 安装**：安装时使用精确版本 URL；`latest.txt` 只供人阅读。

## 5. 冒烟验证

### 5.1 快速验证（已有测试 profile）

如果测试 profile 之前用 `link:` 安装，**必须先移除再安装**。实测直接 `add` 可能显示成功，但 `node_modules/tmsync` 仍是指向源码目录的 junction（pnpm 报 `Already up to date`），实际加载的仍是源码：

```powershell
dsh plugin --profile tmsync-test remove tmsync
```

然后安装并验证：

```powershell
dsh plugin --profile tmsync-test add "D:\release\tmsync\v0.2.3\tmsync-0.2.3.tgz"
dsh --profile tmsync-test --dump-config | Select-String -Pattern "tmsync|preset-tmsync"
dsh --profile tmsync-test --no-open --port 3091
Get-Item "$env:USERPROFILE\.dsh\profiles\tmsync-test\node_modules\tmsync" | Select-Object LinkType,Target
```

检查：

- 侧边栏出现「测试资产」。
- 新建会话出现「测试资产工作区」（preset `tmsync`）。
- 配置页可打开，「测试连接」可用。
- 选择项目、关联目录、拉取成功。

`LinkType` 为空表示已解压到 profile；如果仍有 `Target`，说明还是链接，需要重新移除安装。

### 5.2 干净用户模拟（可选）

首次会下载 web profile 的依赖，耗时取决于网络。使用临时 `DSH_HOME` 和 `TMSYNC_DATA_DIR` 隔离：

```powershell
$smoke = Join-Path $env:TEMP "tmsync-smoke"
Remove-Item $smoke -Recurse -Force -ErrorAction SilentlyContinue
$env:DSH_HOME = Join-Path $smoke "dsh"
$env:TMSYNC_DATA_DIR = Join-Path $smoke "tmsync"

dsh plugin --profile web add "D:\release\tmsync\v0.2.3\tmsync-0.2.3.tgz"
dsh --profile web --dump-config | Select-String -Pattern "tmsync|preset-tmsync"
dsh --profile web --no-open --port 3092
```

验证完成后关闭该终端，或在当前终端清空环境变量，避免污染日常配置。

### 5.3 GUI 安装验证

在 `dsh web` 的「插件」页用 tarball 绝对路径安装一次，确认：

- 安装对话框接受该 spec。
- 安装完成后插件列表显示 `tmsync` 与版本号。
- 刷新浏览器后侧边栏出现「测试资产」。
- 卸载/重装流程可用。

### 5.4 升级与卸载

- 升级：安装新版本 tarball；如果版本号未变化或被 pnpm 判定 `Already up to date`，先 `remove` 再安装。重启 `dsh web`，确认版本号变化。
- 卸载：`dsh plugin --profile tmsync-test remove tmsync`，确认 profile 清单中移除。
- 回滚：安装上一版本 tarball。

## 6. 发布公告模板

```text
【tmsync v0.2.3 发布】
适用：DSH >=0.2.1 <0.3.0（已在 0.2.2-rc.1 冒烟）；仅 web profile；Node 以 DSH 要求为准。
安装：dsh plugin --profile web add "https://files.example.com/tmsync/v0.2.3/tmsync-0.2.3.tgz"
SHA256：<填写 dist/tmsync-0.2.3.sha256 的值>
升级：安装新版本后重启 dsh web；tarball 安装没有 GUI 一键更新。
回滚：安装上一版本 tarball。
变更：见 CHANGELOG.md。
注意：工作台仅本机 loopback 访问，不要用局域网 IP 或反向代理打开。
```

## 7. 回滚与撤回

- 保留旧版本 tarball，不要删除用户可能已记录的 URL。
- 弃用某版本时，在该版本目录放 `DEPRECATED.txt`，说明原因和建议版本；不要直接删除文件。
- 用户回滚 = 安装旧版本 tarball，然后重启 `dsh web`。
- 安全修复优先发新版本；撤回旧版本前先公告，并提醒用户重新安装。

## 8. 后续可选：内网 npm registry

若以后有 Verdaccio / Nexus 等内网 registry，可获得 GUI 的版本检查与一键更新：

1. 将包名改为 `@<scope>/tmsync`，并同步修改第 2.2 节的 3 处引用。
2. 删除 `package.json` 的 `"private": true`，补 `publishConfig`（registry/access）。`release:check` 会提示 `package is not private` 警告，确认这是有意发布到 registry。
3. 配置 `.npmrc` 认证，执行 `npm publish --registry <url>`。
4. 用户改为 `dsh plugin --profile web add "@<scope>/tmsync@<version>"`。

本文档不包含 registry 的实际配置与 CI 发布；需要时再单独落地。
